## 2. 逐项修改

### 2.1 整体黑白灰，包括图标

- `Theme.cs` 全部颜色改为中性灰阶：背景、面板、卡片、边框、文字、强调色/选中态、危险提示、棋盘格均为黑/白/灰，无彩色强调色。
- 主按钮/选中项使用浅灰底 + 深色文字；滑块/开关/选中边框使用白色或浅灰。
- `assets/app.ico` / `app.png` 重新生成：浅灰圆角方块 + 深灰卡片 + 白/灰图形，全部灰阶；已嵌入 exe，标题栏/右键菜单图标同步。32×32 提取验证通过。
- UI 中仍会显示用户自己的彩色图片（这是内容，不属于界面配色）。

### 2.2 输入框支持键盘输入

- `Stepper` 由纯自绘值改为“自绘外框 + 内嵌原生 TextBox”：
  - 点击数字区域即可获得焦点、全选；
  - 键盘输入数字，`Enter` 提交，`Esc` 取消，失焦自动提交；
  - 非法输入回退旧值，超范围自动 clamp；
  - 保留左右 `− / +` 按钮、滚轮微调、方向键。
- 涉及：图片间距、外边距、输出尺寸数值。快捷键/鼠标操作不冲突。

### 2.3 背景颜色文本不再重叠、不显示色值

- 删除原 `#AARRGGBB` 色值文本。
- 只保留颜色名称文本：`透明 / 白色 / 黑色 / 自定义`。
- `ColorSwatchButton` 的“色块 + 名称”高度、字号、边距随 DPI 缩放，避免 200% DPI 下名称压到色块/下一行。
- 白色预设改为纯白 `#FFFFFF`，与 JPG 透明压白保持一致。

### 2.4 透明度滑块简化

- 去掉滑块的背景框/渐变底/边框，只显示：一条细指示条 + 圆形滑块。
- 已填充部分为白色，未填充为灰色，滑块为深底白边。
- 文本改为同一行左对齐“透明度”、右对齐百分比数值，位于滑块上方，不再与颜色名称重叠。
- 无 hex 色值文本。

### 2.5 gap=0 仍有缝

- 根因 1：预览缩放时分别对每张图的 X 和宽度四舍五入，gap=0 时相邻边界可能差 1px；现在改为边界取整（x1=round(X*s)、x2=round((X+W)*s)、宽=x2-x1），相邻图严格相接。
- 根因 2：GDI+ 双三次插值会在图片边缘采样到透明，形成半透明缝；`Compose`/`ComposePreview`/缩略图缩放统一使用 `ImageAttributes.WrapMode.TileFlipXY`，消除边缘透明采样。
- 像素级验证：
  - 两张 40×20 图、透明背景、gap=0、`--out-width 2000` → 输出 2000×500；边界列 x=999 红 255 alpha、x=1000 绿 255 alpha；translate=0，无透明/背景色列。
  - 纵向 gap=0、`--out-height 120` → 120×120；分界行同样实色。
  - Core 测试共 69/69 通过，其中新增 gap=0 横/纵/预览/JPG/大图缩略图无缝测试。

### 2.6 中位数解释

- UI“自动”尺寸改为“自动：取图片中间尺寸”，并增加 tooltip：
  “取所有图片高度/宽度的中位数作为拼接基准，避免个别超大或超小图片把整体尺寸带偏。”
- 中位数 = 把 n 张图的高度（横向）或宽度（纵向）排序，取正中间位置那个值；偶数张取中间两个的平均值。
- README 与使用说明已补充完整解释。

### 2.7 手动指定最终宽度/高度（只能设一个）

- “拼接尺寸”改为“输出尺寸”：
  - 模式：`自动` / `指定宽度` / `指定高度`；
  - 选“指定宽度/高度”后出现一个数值框（可键盘输入），另一项在下方以“高度自动 X px”/“宽度自动 Y px”显示；
  - 自动模式仍基于中位数生成自然布局。
- 语义：先按中位数生成自然布局，再整体等比缩放到目标轴；目标轴精确等于设置值，另一轴按比例四舍五入。
- 实测：
  - 自然 3606×932，指定宽度 2000 → 2000×517；
  - 指定高度 932 → 3606×932（与原自动一致）；
  - 两张 40×20 横向 gap=0，指定宽度 2000 → 2000×500；
  - 纵向 gap=0，指定高度 120 → 120×120；
  - 尺寸超 80MP/单边 32000 时自动缩小并标记提示。
- 说明：整体缩放会同步缩放间距/边距（相对比例不变），这一点已写入 README。

## 4. 已知边界

- Win11 一级菜单仍需 MSIX 签名，本轮保持经典菜单方案。
- 固定尺寸为整体等比缩放，间距/边距会随比例缩放；若需“间距固定像素、只调图片尺寸”的语义请再提出。
- 80MP 极端输出编码仍可能较慢，属既有性能边界。
- HEIC/AVIF 仍依赖系统 WIC 解码扩展（当前机器已验证真实样本可解码）。
